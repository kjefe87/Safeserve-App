# SafeServe — Next.js app

Airtable is the database. Next.js (App Router) is the front end. Hosting: Vercel free tier.

## Pages
| Page | Who | What |
|---|---|---|
| `/login` | all | Email + PIN (bcrypt hash in the `PIN Hash` field) |
| `/dashboard` | all | Role-aware navigation |
| `/checklists` | all | Mark tasks complete; writes an audit row to Compliance Logs |
| `/temp-logs` | all | Log temperatures; corrective action required when out of range |
| `/issues` | all report; Owner/Manager manage | Report, assign, set due date, resolve (notes required) |
| `/compliance-logs` | Owner/Manager | Read-only audit trail |
| `/staff-certs` | Owner/Manager | Certifications and expiry status |
| `/inspection-report` | Owner/Manager | Live snapshot, saved reports, and a downloadable PDF per report |

## Setup
1. `npm install`
2. Copy `.env.local.example` to `.env.local` and fill it in.
3. Set each user's PIN: `node scripts/set-pin.js someone@example.com 1234`
4. `npm run dev`

## How it works (things worth knowing)
- **All schema names live in two places:** table names in `lib/airtable.js` (`TABLES`) and
  dropdown values in `lib/schema.js`. Several Airtable options have trailing spaces
  (`"Completed "`, `"In Progress "`, `"Ready "`) and are matched exactly there.
- **Linked fields** (Task, Completed By, Reported By, Assigned To, Logged By, Generated By)
  are written as record IDs.
- **Every record is scoped by `Restaurant Name`.** Rows with a blank Restaurant Name are
  invisible to the app. Always set it on records created by hand or by Make.com.
- **Checklist "done" is computed per restaurant** from Compliance Logs inside the task's window
  (Per Shift = AM/PM half-day, Daily = today, Weekly = since Monday, Monthly = since the 1st,
  New York time). `Checklists.Status` is still written for any Make.com scenario that reads it,
  but the app ignores it.
- **API routes re-check the user in Airtable** (cached 60s), so deactivating someone or
  changing their role takes effect within about a minute. Sessions last 12 hours.
- **Login is throttled** (5 failures / 15 min per email + IP), in memory per server instance.

## Known limits
- Photo uploads aren't supported (Airtable's API needs a hosted file URL).
- Report PDFs are built on demand by the app (`lib/reportPdf.js`, pdf-lib) from a snapshot saved
  on the report record (`Issues Snapshot` field). Reports created before that field existed
  download with counts only. The PDF is not stored back in Airtable's `Report PDF` field.
- 4-digit PINs are weak by nature. The throttle slows guessing but isn't a hard guarantee.
- `npm audit` flags PostCSS inside Next.js; this app never processes untrusted CSS.
  Revisit when upgrading to Next 16.
